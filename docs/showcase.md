# Живая витрина Immersive Cases

Это две разные вещи: **редакционный каталог из семи реальных проектов** уже работает без ключа, а **автоматический сбор черновиков** ждёт ключ AI Tunnel. Нет вымышленных записей, тестовых страниц или выдачи черновиков за проверенную коллекцию.

## Открыть и показать

- `Immersive_Cases_Витрина.html` — автономный снимок, открыть в браузере как обычный файл. Поиск, фильтры, карточки и экспорт работают без сервера. Источники открываются по интернету. Снимок не обновляется сам.
- Из корня проекта в активном окружении: `python -m services.showcase`. Открыть http://127.0.0.1:5002/. Создаётся отдельная временная SQLite, рабочая база не трогается. Без ключа.
- Маршрут показа: «Rain Room · Шарджа» → оценка 4/4 → что происходит с дождём → источник. Затем сбросить поиск и выбрать «Сенсорный маршрут», чтобы показать, что иммерсивность бывает без управления пространством.
- В оформлении использована собственная схематическая иллюстрация дождя, а не выдаваемый за документальный кадр рендер. Фото и видеоролики не копируются; на страницах источников есть материалы правообладателей.

## Почему выставлены разные оценки

Шкала **1–4** предметная и редакционная, не отзыв о качестве, не пользовательская статистика, не балл алгоритма поиска. Уровни нельзя суммировать с оценкой интерактивности. Храним код уровня в совместимом числовом поле (25 × уровень), интерфейс выводит уровень только для метода `editorial_immersion_v1`. Если доказательств мало, оценку не выставляем.

| Уровень | Условие | Пример |
|---|---|---|
| 1 | Фокус на одном экране или объекте в обычном пространстве | Unsupervised: масштабный экран и звук в лобби, реакция на среду отдельно |
| 2 | Архитектура или несколько поверхностей составляют оболочку сцены | Klimt: изображение занимает стены бывшего цеха |
| 3 | Маршрут, виртуальное пространство или несколько согласованных ощущений образуют единый опыт | Dreamachine, Works of Nature, THE INFINITE |
| 4 | Тело физически находится внутри основного эффекта | Rain Room: человек в реальном дожде; teamLab Planets: человек стоит в воде, через которую идёт проекция |

Отличаем даты отдельного показа от даты создания работы и не утверждаем, что давно открытая выставка сегодня принимает посетителей. В наборе: Япония, ОАЭ, США, Великобритания, Австралия, Канада и Франция. У каждого события есть ссылка и короткая цитата о проведении и механике. Редакционные формулировки на русском; цитаты остаются на языке источника.

## Первый автоматический сбор

1. Скопировать `immersive_pipeline/.env.example` в `immersive_pipeline/.env` только если файла ещё нет. Заполнить `AITUNNEL_API_KEY` локально. Остальное можно оставить по умолчанию.
2. Запустить `python -m services.collect_pilot` либо `powershell -ExecutionPolicy Bypass -File .\pilot.ps1`. Максимум **13 запросов**, из них один проверочный. Шлюз не повторяет запросы от имени приложения; лимит попыток приложения не ограничивает деньги в кабинете. Сперва проверьте бюджет ключа там.
3. Пилот читает двенадцать международных проектных страниц из `immersive_pipeline/seeds.international.json`. Успешные страницы сохраняются в `data/pilot/`; страницы с ошибкой не помечаются обработанными. Ответ модели с нулём кейсов допустим; число результатов не гарантируется. При ошибке ненулевой код возврата сохраняется, импортируются только накопленные карточки.
4. Результат хранится отдельно от редакционной витрины: `data/pilot-preview.sqlite3`. Его можно открыть под `--include-drafts` только на localhost. Первый живой прогон описан в отчёте из архива; доступность сайтов также зависит от сети машины запуска.

## Проверка и приём новых карточек

```powershell
python -m services.review --db data/pilot-preview.sqlite3 list
python -m services.review --db data/pilot-preview.sqlite3 show ID
python -m services.review --db data/pilot-preview.sqlite3 approve ID --by "Имя редактора" --reason "Проверены даты, место и механизм по источникам" --level 3
```

Сначала прочитать источники: совпавшая цитата ещё не доказывает вывод модели. Без подтверждения проведения, места и механизма одобрение не проходит, решения записываются в журнал SQLite. `reject` и `needs-review` используют те же `--by` и `--reason`. Команды работают только с явно указанной локальной БД. Правки и обогащение фактов ведутся через входной контракт, экран редактирования пока не добавлен. Веб-API остаётся только для чтения.

Расширение: после аудита пилота добавить проверенную группу страниц музеев и студий на следующем языке, измерить выход карточек и стоимость, затем включить новые источники партиями. Не начинать с массового обхода или автоодобрения.

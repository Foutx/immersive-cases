# Настройки и формат данных

Основная инструкция: [README проекта](../README.md). Все команды там выполняются из корня.

## Провайдеры LLM

| LLM_PROVIDER | Настройки |
| --- | --- |
| `gigachat` | `GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE`, `GIGACHAT_MODEL` (в примере GigaChat-2-Max) |
| `ollama` | `OLLAMA_URL`, `OLLAMA_MODEL`; сервер и модель должны быть запущены локально |
| `openai` | `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL` |
| `none` | На этапе 1 импортируются только ручные кандидаты |

При отсутствии `.env` провайдер в `config.py` — Ollama. Скопированный `.env.example` выбирает GigaChat.
Параметр командной строки `--llm` переопределяет выбор провайдера.

GigaChat выполняет запросы последовательно, обновляет OAuth-токен и повторяет запрос при HTTP 401.
По умолчанию используется короткий запрос без принудительной схемы (`GIGACHAT_STRUCTURED=0`).
При неверном JSON одна попытка исправления включает предыдущий ответ; повторная ошибка
останавливает этап 1. Режим `GIGACHAT_STRUCTURED=1` экспериментальный.

## Основные настройки

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `FINAL_COUNT` | 100 | Требуемое число карточек при публикации |
| `TARGET_POOL_MAX` | 300 | Верхняя граница пула кандидатов |
| `MAX_PER_AGENCY` | 12 | Лимит по первой студии в списке авторов |
| `CRAWL_MAX_PAGES_PER_SEED` | 40 | Максимум ссылок одного каталога |
| `LLM_MAX_INPUT_CHARS` | 12000 | Максимум символов страницы для LLM |
| `VIDEO_RELEVANCE_THRESHOLD` | 0.5 | Порог текстовой релевантности видео |
| `MAX_QUERIES_PER_CASE` | 14 | Лимит поисковых запросов на кейс |
| `MAX_VIDEOS_PER_CASE` | 5 | Цель по подтверждённым видео, лимит экспорта |
| `SEARCH_BACKENDS` | youtube,vimeo,duckduckgo | Используемые поисковые сервисы |
| `USE_CRAWL4AI` | auto | auto / yes / no |
| `SUMMARY_LANGUAGE` | ru | Запрашиваемый язык описания |

Параметры задаются через `.env` рядом с `config.py`. Не все константы настраиваются окружением:
диапазон лет, веса и квоты категорий изменяются непосредственно в `config.py`.
Относительные пути в настройках и `--publish` отсчитываются от текущей рабочей папки.

## Оценка и баланс

Веса: интерактивность 25, технологии 25, масштаб 15, цитируемость 20, видео 15.
Это эвристики по тексту и метаданным, а не экспертная оценка качества проекта.

| Категория | Квота |
| --- | --- |
| Museums & Cultural Exhibitions | 30 |
| Brand Activations & Corporate Shows | 30 |
| Festivals & Public Art | 25 |
| Immersive Performance & Theatre | 15 |

Недобор категории заполняется другими кейсами. Лимит студии не ослабляется;
поэтому итог может быть меньше FINAL_COUNT. При изменении FINAL_COUNT согласуйте квоты.

## Поля итоговой карточки

| Поле | Содержание |
| --- | --- |
| `id` | Автоматический хэш бренда, названия и года |
| `title` | Название проекта |
| `brand_or_client` | Бренд или заказчик |
| `year` | Год в допустимом диапазоне |
| `country_city` | Страна и город |
| `category` | Одна из четырёх категорий |
| `immersive_format` | Формат взаимодействия или показа |
| `tech_markers` | projection_mapping, interactive_generative, spatial_audio, xr, kinetic |
| `summary` | Описание; модель получает инструкцию писать 2–4 предложения |
| `source_url` | Ссылка на источник |
| `video_urls` | Непустой список ссылок на подтверждённые видео |

Схема проверяет длины и типы полей; она не проверяет достоверность фактов, число предложений
или наличие реального города внутри строки country_city. JSON Schema экспортируется этапом 4.

## Источники и ручной импорт

В `seeds.json` для источника задаются `name`, `kind`, `url`, `follow_pattern` и необязательное
`enabled`. Регулярное выражение проверяет путь ссылки без query-параметров. Обход остаётся
на том же хосте. `default_brand` — явно заданный бренд источника, используемый только если
модель не указала свой; сейчас это правило настроено для teamLab.

Пример ручного импорта: [manual_candidates.example.json](data/manual_candidates.example.json).
Скопируйте его в `data/manual_candidates.json`, замените пример своими проверенными фактами
и запустите `stage1 --llm none`. Реальные ручные карточки не включаются в Git по умолчанию.

`data/existing_cases.json` содержит исключаемые из сбора проекты. Обычно достаточно названия,
бренда и года. Дополнительные файлы задаются `EXISTING_CASES`: разделитель `;` в Windows
и `:` в Linux/macOS. Если список содержит внутренние данные, не коммитьте его заполненным.

## Ограничения видео

Четыре группы запросов: студии, визуальные признаки, место/даты, обзоры посетителей.
Запросы чередуются, чтобы одна группа не заняла весь лимит.
Фильтр дат применяется поиском YouTube; другие сервисы не гарантируют такое же окно.
Неизвестная дата публикации не является автоматическим запретом.

Подтверждение доступности поддерживается для YouTube/Vimeo через oEmbed.
Другие платформы могут обнаруживаться, но не получают verified автоматически.
После изменения исходных карточек или старых правил верификации запускайте `stage2 --force`.

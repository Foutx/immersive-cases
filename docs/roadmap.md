# Immersive Cases: что сделано и что дальше

## Уже в этой версии

- Сборщик переключён на AI Tunnel, модель **GPT‑4.1 Nano**. ID модели можно изменить в `immersive_pipeline/.env`, не трогая код. GigaChat остаётся ручным резервом.
- По умолчанию максимум 60 попыток AI Tunnel за запуск, максимум 12 000 символов страницы на входе, максимум 1 400 токенов ответа на карточку и 256 на поисковые запросы. Нет скрытого перехода на дорогую модель или автоматического повтора. CLI показывает число попыток и полученный от шлюза usage. При сетевом сбое фактические списания уточняются в кабинете, даже если usage не вернулся.
- В карточку попадает не только «мэппинг/VR», но и что окружает посетителя, что он делает, реагирует ли пространство, какая у него роль и как создаётся эффект присутствия. Сохраняются только цитаты, которые нашлись в переданном тексте страницы; пробелы нормализуются. URL берётся у реально загруженной страницы. Это проверка происхождения цитаты, а не доказательство того, что модель правильно её истолковала.
- Эти сведения проходят до SQLite без изменения исходной схемы итогового JSON. Сайт выделяет механизм с цитатой, показывает отдельный блок и позволяет фильтровать и выгружать карточки по этому признаку. Публикации нет, записи после сбора остаются черновиками.

## Цена и выбор модели

Тарифы AI Tunnel в ₽ за 1 млн токенов, на момент проверки:

| Модель | Вход | Выход | Пример: 1 000 запросов по 3 000 входных и 600 выходных |
| --- | ---: | ---: | ---: |
| [GPT‑4.1 Nano](https://aitunnel.ru/faq/skolko-stoit-gpt-4-1-nano) | 20 | 80 | 108 ₽ |
| [GPT‑4o Mini](https://aitunnel.ru/faq/skolko-stoit-gpt-4o-mini) | 30 | 120 | 162 ₽ |
| [GPT‑3.5 Turbo](https://aitunnel.ru/models/gpt-3-5-turbo) | 100 | 300 | 480 ₽ |

Это оценка LLM, не счёт за сбор тысячи кейсов: некоторые страницы не дадут карточку, поиск видео и другие сервисы считаются отдельно. Начинаем с Nano. Если он заметно проигрывает на сложных страницах, сравниваем 4o Mini на той же выборке и переключаем только там, где есть выигрыш. Без платного автоматического каскада.

## Очерёдность доработок

1. **Пилот и метрики качества.** После `llm-check` взять 20–30 страниц разных типов и языков: выставки, театр, инсталляции и отрицательные примеры, включая каталог без фактов и обычную световую сцену. Отдельно разметить год, место, факт проведения, механизм и интерактивность. Сравнить долю корректных карточек и цитат, пропуски, дубли, стоимость на одну принятую карточку. Ориентир перед расширением: ≥90% правильно разобранных обязательных полей на размеченных положительных примерах и ни одного неподтверждённого «проведено» в публикации. Не допускать карточки к публикации только по баллу модели.
2. **Локальная проверка карточек.** Список черновиков: исправление полей, просмотр цитаты рядом с первоисточником, отметки «нет доказательства» и «конфликт источников», решение «принять/отклонить» и история. Запись сначала только локально, за отдельной авторизацией; публичный API оставить читающим. Публиковать после ручного подтверждения проведения, места и механизма, а не по ключевому слову immersive.
3. **Расширение базы без мусора.** Добавить студии, музеи и премии из недопредставленных стран и языков. Развести столбцы «иммерсивность» и «интерактивность»: пассивная 360° среда может быть иммерсивной, а сенсор сам по себе ничего не доказывает. Ввести кэш по хэшу очищенного текста, ID модели и версии промпта; хранить снимок источника или его хэш для повторной проверки и исключать дубли по конкретному показу, а не названию. Добавлять источники волнами по 10–20 прошедших модерацию кейсов.
4. **Сайт как инструмент поиска референсов.** Фильтры по механике (реакция на шаги, аудиомаршрут, 360° и т. п.), роли посетителя и типу доказательства; сохранение подборок и сравнение карточек рядом. Добавлять видео-превью только с разрешёнными материалами. После наполнения каталога отдельно проверить мобильную выдачу, скорость и пустые состояния.
5. **Эксплуатация после пилота.** Простой регулярный сбор с бюджетом и отчётом об ошибках источников, резервное копирование SQLite и журнал ручных решений. Решение о размещении и доступах после того, как команда утвердит правила модерации и первые кейсы.

## Первый локальный прогон

Из корня проекта в PowerShell (с активированным окружением Python):

```powershell
python immersive_pipeline/main.py llm-check
$env:DATA_DIR = "data/pilot"
python immersive_pipeline/main.py stage1 --seed teamLab --limit 3
python immersive_pipeline/main.py import-db --input data/pilot/raw_candidates.json --db data/pilot-preview.sqlite3
python -m api.app --db data/pilot-preview.sqlite3 --include-drafts --port 5002
```

Просмотр на http://127.0.0.1:5002/. Для обычного режима не используйте `--include-drafts`.
Если сбор не добавил ни одной карточки, перед импортом проверьте лог и файл с кандидатами.
Используйте отдельный `DATA_DIR` для сравнения моделей: текущие контрольные точки не очищаются при смене провайдера. Для полного сбора после достижения лимита запустите тот же этап снова: завершённые страницы пропускаются. Не коммитьте файл `.env`, а для платных проверок задайте лимит и в кабинете AI Tunnel.

**Граница текущей работы:** тесты используют заглушку API и временную SQLite. В отдельном живом пилоте проверены реальный ответ AI Tunnel, парсинг и SQLite. Точность ограничена: настоящие карточки не заменяют редакционную проверку; см. HTML-отчёт. Старые демонстрационные карточки не опубликованы. Архив не меняет GitHub или рабочий сайт.

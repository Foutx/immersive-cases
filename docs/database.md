# Локальная база без Docker

Используется SQLite из стандартной библиотеки Python. Никаких серверов, паролей и установки пакетов для подключения не нужно.

Из корня репозитория:

```powershell
python -m database.check
```

Команда создаст `data/immersive_cases.sqlite3`, проверит чтение и запись. Таблицы мероприятий создаются командой `python -m database.migrate`. Файл не попадает в Git. Относительный путь всегда считается от корня проекта, независимо от рабочей папки терминала.

Для другого пути можно задать переменную окружения DATABASE_PATH. Файл .env не требуется и автоматически не читается.

В коде используется `from database.connection import connect`. Контекст `with connect() as db` фиксирует успешные изменения, откатывает их при исключении и закрывает соединение. Внешние ключи включены, режим WAL разрешает чтение во время записи; одновременно пишет один процесс. SQLite подходит для текущей локальной разработки. Для нескольких одновременно пишущих сервисов вернёмся к PostgreSQL; это потребует переноса схемы и данных, а не только смены адреса подключения.

Не копируйте только основной файл во время работы: актуальные изменения могут быть в WAL. Для резервной копии используйте sqlite3.Connection.backup либо остановите все подключения перед копированием.

Проверки: `python tests/test_database_connection.py`.


## Создание и обновление таблиц

```powershell
python -m database.migrate
```

Команда применяет SQL-файлы database/migrations/ по порядку. Повторный запуск безопасен: версии и SHA-256 записываются в schema_migrations. Уже применённые файлы нельзя изменять; создавайте следующий файл 002_*.sql. Изменение применённого файла или неизвестная версия базы вызывают ошибку. Все новые миграции одного запуска выполняются одной транзакцией с блокировкой записи; при ошибке изменения откатываются. Автоматического отката версий вниз нет. Перед будущими изменениями рабочей базы делайте резервную копию.

## Таблицы

| Таблица | Назначение |
| --- | --- |
| events | Карточка события, даты, место, рейтинг и статус модерации |
| event_sources | Уникальное соответствие producer + source_record_id внутреннему ID |
| event_parties | Организаторы и студии с отдельными ролями |
| event_proofs | Источники и результаты проверки ссылок |
| event_claims | Утверждения об иммерсивности, месте, датах и проведении |
| claim_evidence | Цитаты и привязка утверждения к источнику того же события |
| tags / event_tags | Справочник и связи форматов/технологий |
| import_runs | Запуски импорта, итоги и счётчики |
| scrape_logs | История обходов страниц, ошибки и хеши |
| schema_migrations | Версия схемы и контрольные суммы |
| events_fts | Полнотекстовый индекс названия и описания |

SQLite хранит ID события как TEXT; будущий сервис импорта будет выдавать UUID. Отдельные строки не получают случайный ID автоматически. Даты и время хранятся в ISO-формате; время сервис должен нормализовать в UTC. Строгий разбор дат и URL выполняется контрактом перед записью. База дополнительно контролирует порядок дат, диапазоны значений, статусы, уникальность и внешние ключи.

Новый event имеет статус draft. Для published нужны reviewed_by и reviewed_at. Это минимальное ограничение схемы, не полноценная проверка правил публикации: наличие доказательств проведения и иммерсивности должен проверить будущий сервис модерации. Аналогично минимум одна цитата на утверждение и присутствие первоисточника в proofs обеспечиваются контрактом/будущим импортом в общей транзакции.

updated_at обновляет будущий сервис записи; база пока задаёт его только при создании. Подтверждения, утверждения, связи и внешние ключи события удаляются каскадно. Общие теги и журналы автоматически не удаляются. Удаление запуска сохраняет scrape_logs с пустым run_id.

Индексы предусмотрены по стране/году, году, статусу модерации, окончанию события, типу/дате проверки подтверждения, тегам и журналам. FTS5 синхронизируется триггерами при вставке, изменении и удалении. Unicode-поиск поддерживает кириллицу, но не выполняет морфологический или семантический анализ. Интерфейс поиска будет добавлен отдельно.

## Проверки

```powershell
python tests/test_database_schema.py
python tests/test_database_connection.py
python tests/test_contract.py
```

При реализации проверены 7 тестов схемы, 2 подключения и 13 контракта. В рабочей базе созданы только таблицы: тестовые мероприятия используются во временных файлах. Импорт старой базы автоматически не выполняется.

Миграция 002_import_records.sql добавляет историю входных карточек и конфликтов. Импорт: [import.md](import.md).

# Как запустить поиск по 100 кейсам и собрать свою базу

Для демонстрации используйте готовые 100 мероприятий из `cases.json`. Поиск по ним работает офлайн. Интернет понадобится для нового сбора и проверки доступности ссылок.

## 1. Откройте папку проекта

Распакуйте архив «Сбор и поиск кейсов.zip» в одну папку. Откройте эту папку в Проводнике, введите `powershell` в адресной строке и нажмите Enter. В открывшемся окне выполните:

```powershell
python --version
```

Подойдёт Python 3.10 или новее. Если Windows не находит команду `python`, попробуйте `py --version` и далее используйте `py` вместо `python`. В исходной папке проекта также можно использовать `.\.venv\Scripts\python.exe`.

## 2. Проверьте готовую базу и запустите поиск

```powershell
python cases_pipeline.py validate
python case_search.py "мастер-класс по керамике"
python case_search.py "инклюзия в библиотеке"
```

После проверки ожидайте сообщение `Проверено карточек: 100`. Поиск выводит до пяти результатов. У каждого есть идентификатор `id`, степень совпадения `close` или `partial` и объяснение. Чтобы открыть запись мероприятия, найдите этот `id` в `cases.json` и перейдите по ссылке из поля `source_url`.

## 3. Соберите отдельную базу из интернета

```powershell
python cases_pipeline.py --db collected.json collect --limit 100 --pages 30
python cases_pipeline.py --db collected.json validate --links
python case_search.py --db collected.json "театр"
```

Сборщик читает страницы архива трансляций «Культура.РФ», переходит на страницы мероприятий и ищет метаданные видеозаписи с адресом плеера или файла. Трейлер или анонс сам по себе не подходит. Дата в автоматически собранной карточке обозначает дату архивной трансляции. Тема и площадка заполняются из данных портала. Поле результата предназначено для подтверждённых итогов мероприятия. Повторный запуск ищет следующую порцию новых карточек в заданном диапазоне страниц. Предел на страницы может дать меньше запрошенного количества. При сетевой ошибке текущая операция завершается без записи частичного результата.

Для быстрой проверки замените `--limit 100` на `--limit 3`. В конце программа сообщит, сколько карточек добавлено и сколько всего лежит в файле.

## 4. Импортируйте свои карточки при необходимости

```powershell
python cases_pipeline.py --db collected.json import incoming.json
python cases_pipeline.py --db collected.json import incoming.csv
```

JSON должен содержать массив объектов, CSV — заголовки с именами полей из cases.json. Списки в CSV можно записать как JSON-массив или разделить точками с запятой внутри одной ячейки. При импорте обязательны название, описание в 2–4 предложениях и ссылка на источник. Если идентификатор пропущен, программа создаёт стабильный идентификатор по ссылке. Карточки с совпадающими идентификатором, ссылкой или комбинацией названия, даты и города объединяются. Существующие сведения имеют приоритет, списки материалов пополняются.

Для контрольной выборки передайте `--eval-file eval_100_cases.json` **перед** командой `collect`, `import` или `validate`. При записи совпадения исключаются из поисковой базы. Файл контрольной выборки должен быть отдельным.

Пример проверки пересечений, если есть файл контрольных кейсов:

```powershell
python cases_pipeline.py --db collected.json --eval-file eval_100_cases.json validate
```

## Какие файлы за что отвечают

- `culture_archive.py` читает каталог и извлекает подтверждения записи.
- `cases_pipeline.py` собирает, импортирует, объединяет и проверяет карточки.
- `case_search.py` запускает поиск и предоставляет функцию `search_cases(query, cases, limit=5)`.
- `cases.json` содержит исходную ручную подборку из 100 карточек. Новый сбор формирует собственную выборку в порядке каталога.
